# 产品规格 · 住回本

## 1. 命题与定位

**对应赛道**：2026 飞猪 AI 旅行创新大赛 · 预设命题第 2 条「高品质酒店 staycation——AI 如何帮不同用户发现酒店内外最值得体验的部分，让一次入住成为一段完整旅程？」

**决策链占位**：

```
选哪家酒店   →  这单花多少钱  →  住进去这 45 小时怎么过
  #186 住哪好      #179 纯过日子     ← 住回本（空位）
  #217 狗拿主意
```

不排序、不比总价、不筛选，只处理"已经决定住这家"之后的事。

## 2. 用户与场景

| 场景 | 用户原话 | 产品要回答的问题 |
| --- | --- | --- |
| 囤货后悔 | "双十一囤了 2 晚含早套餐，周五去能用吗" | 有效期、可用星期、加价日、早餐够不够 |
| 带娃补差 | "孩子 1.25 米，套餐写 1.2M 以下" | 免票成不成立、补差多少、要不要换房型 |
| 纯宅躺平 | "我根本不打算出门，这酒店值不值" | 步行半径里有几处真能走到的、酒店内有什么权益 |
| 商务误判 | "看名字有江景就订了两晚" | 周边是否 0 处可达、45 小时会不会变成困在房间 |

四个人群，同一套规则，四种结论。

## 3. 产品机制（四层）

### 第 1 层 套餐权益解析（模型）

输入 `search-marriott-package` 的 `title + sellPoint`，输出结构化权益：

- 晚数、早餐份数、可用星期窗口、加价日与金额
- 有效期、儿童身高上限、是否含会员积分房晚
- 权益清单（早餐 / 午市 / 下午茶 / 自助晚餐 / 迷你吧 / 欢迎饮品）

三条硬规矩：

1. 每个字段必须带原句证据（`evidence`），没有证据不落地
2. 有歧义不猜（例如"2 晚连住含 2 早"里"2 早"是总量还是每晚），写进 `ambiguous`
3. 解析不出来的写进 `missing`，交给规则层判 `UNKNOWN`

### 第 2 层 时间轴编排（模型 + 规则）

- 固定锚点：15:00 入住、23:00–07:00 睡眠（每晚 8h）、11:30–12:00 退房
- 套餐权益按语义偏好时间落位（晚餐 18:30、早餐 07:30、下午茶 15:00）
- 周边 POI 只放步行可达的，且全部标「待核」（接口不返回开放时间）
- 首选时间被占则就近改期（例：11:00 午市撞上 11:30 退房 → 提前到 10:00）
- 放不下的进 `rejected`，**不静默丢弃**
- 剩余空档显式标「留白」，不硬塞

### 第 3 层 确定性校验（代码，9 条）

| 规则 | 检查内容 | 输入字段 |
| --- | --- | --- |
| R1 | 套餐有效期 vs 离店日期 | `valid_until` |
| R2 | 可用星期 vs 入住日 | `weekday_window` |
| R3 | 加价日 × 间夜数 → 加价金额 | `surcharge_days` / `surcharge_amount` |
| R4 | 周末是否触发加价 | `weekend_no_surcharge` |
| R5 | 儿童身高 vs 免票门槛 | `child_height_max_m` |
| R6 | 早餐份数 vs 成人 × 晚数 | `breakfast_count` / `ambiguous` |
| R7 | 边际成本（房费已沉没，只算增量） | `price_value` / `price_is_from` |
| R8 | 步行半径：haversine ÷ 步速 | 酒店 + POI 坐标 |
| R9 | 餐段权益 vs 12:00 退房 | `entitlements` |

原则：**能用算的不用猜**。R3 的加价金额、R6 的缺口份数、R8 的步行分钟，全部是可复算的数字。

### 第 4 层 交付物（单文件 HTML）

一页看完：结论四宫格 → 9 条核验（按严重度排序，带原句）→ 45 小时时间轴 → 步行半径榜 → 套餐原文 → 数据边界声明。

## 4. 三个 demo 脚本

**Demo 1 · 囤货后悔**
AC 欧轩 2 晚含早套餐，周五入住：
- R3 判定「周二至周四需加价 200 元」**未被触发**（正向验证，不是只挑毛病）
- R6 判定「含 2 早」在 2 晚场景存在歧义 → 待核
- R7 判定「￥998 起/2晚」是起价 → 不给总价

**Demo 2 · 带娃补差**
艾美自助晚餐套餐 + 1.25m 儿童：
- R5 判定免票不成立 → 补差金额接口未返回 → 待核
- 手册顶部出现风险块，而不是"欢迎光临"

**Demo 3 · 纯宅 45 小时**
艾美 2 晚（滨江商务酒店）：
- R8 判定 1200m 内 0 处可达，最近 2722m / 47 分钟
- 时间轴上 25.8 小时留白 → **结论是"这家不值得住两晚"，不是硬凑行程**

## 5. 评审维度对应

**创新性 40%**
- 机制是从"推荐"转向"编排 + 核验"，全池 45 件无同类
- 官方命题原文里的"酒店内外"正好给了绕开缺失字段的口子：内部靠套餐卖点原句，外部靠 POI 坐标

**完整度 30%**
- 端到端可跑：fixtures → 解析 → 9 条规则 → 时间轴 → HTML 手册
- 30 例离线单测，全程不触网（评委 clone 下来直接能验证）
- 每条结论带证据等级，拒绝把"算得出来"当成"查得到"

**市场前景 30%**
- 酒店套餐是飞猪自己在推的品类，`search-marriott-package` 返回 `commissionMoneyYuan`，天然可挂推广者链接
- 延伸 SKU：自助晚餐 / 下午茶 / 中餐厅 / SPA / 延迟退房
- staycation 是高频、可复购、对价格不敏感的场景

## 6. 已知边界与应对

| 边界 | 影响 | 应对 |
| --- | --- | --- |
| 万豪套餐只覆盖万豪系 | 非万豪酒店拿不到权益层 | 双层模式：万豪做深度示范，其余走"酒店 + 周边 POI"降级模式 |
| 无评分/点评（实测 null） | 不能做排序 | 不做排序；用 `listRank` / `decorationTime` / POI `description` 替代 |
| 无 POI 开放时间 | 时间轴不能硬校验 | 全部标待核 + 指向飞猪详情页；人工核验走 `data/manual-notes.json` |
| 价格"起"且无 Key 时脱敏 | 不能给总价 | 只给区间与待核，绝不给假总价 |
| 45 小时可能被质疑 | 需解释口径 | 明文：15:00 入住 + 两晚 + 12:00 退房；并拆出 16h 睡眠 |
